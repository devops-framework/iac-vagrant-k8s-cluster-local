# Hermes project context

## Repository purpose

This repository provisions a local RKE2 homelab Kubernetes cluster with Vagrant + VMware Fusion and Ansible. The supported host path is macOS, including Apple Silicon.

The repository has three related concerns:

- VM lifecycle and SSH bootstrap: `Vagrantfile`
- Cluster and platform provisioning: `ansible/playbook.yml` and `ansible/roles/`
- Application delivery manifests and Helm example: `devops/cd/k8s/` and `app-deploy-example/`

`README.md` is the user-facing source of truth for the network/request path and the normal provisioning workflow.

## Runtime architecture

- Vagrant reads `ansible/inventory.yml`, creates the VM fleet, assigns private-network IPs, and configures the `ubuntu` user and public SSH key.
- Only `rke2-server-001` invokes Ansible provisioning. Ansible targets all inventory hosts.
- The default capability is `cluster`, which maps to the Ansible tag `kubernetes` and installs the RKE2 server, agents, and VIP load balancer.
- The VIP load balancer uses Keepalived + HAProxy. Traffic then enters the Kubernetes ingress controller and is routed to workloads on worker nodes.
- Optional platform capabilities are selected with `VAGRANT_DEPLOY`: `platform-bootstrap`, `argocd`, `github-runner`, or `all`.
- GitOps is the application delivery boundary: Argo CD reconciles application workloads. GitHub runner workloads must not receive application-namespace Kubernetes API access.
- Rancher is not a supported capability unless a real role/manifests are added; do not expose a no-op option.

## Provisioning commands

```bash
vagrant up --no-provision
ansible all -m ping
vagrant provision rke2-server-001

VAGRANT_DEPLOY=platform-bootstrap vagrant provision rke2-server-001
VAGRANT_DEPLOY=argocd vagrant provision rke2-server-001
VAGRANT_DEPLOY=github-runner vagrant provision rke2-server-001
VAGRANT_DEPLOY=all vagrant provision rke2-server-001
```

`VAGRANT_DEPLOY` defaults to `cluster`. Unsupported values must fail fast in `Vagrantfile`; do not silently fall back to another deployment mode.

## Secrets and local-only material

- Never read, print, commit, or modify secret values.
- `ansible/group_vars/master.yml` is local/ignored input; its committed template is `ansible/group_vars/master.example.yml`.
- SSH private keys belong under the ignored `ssh_keys/` directory. `Vagrantfile` consumes the public key and must never embed private key material.
- Prefer Ansible Vault for local secret storage. Argo CD repository credentials must remain read-only and narrowly scoped.
- Do not add credentials, tokens, `.env` files, generated VM state, or `.vagrant/` to the repository.

## Validation gates

Before declaring infrastructure or manifest changes complete, run the repository validator when dependencies are available:

```bash
scripts/validate.sh
```

The validator covers Ruby/Vagrantfile syntax, Ansible syntax, selected Kubernetes YAML, Helm lint/render, Kustomize rendering, optional kubeconform schema checks, optional GitHub Actions `actionlint`, and optional ShellCheck.

For focused changes, also run the narrowest relevant command and inspect the rendered output. Do not claim a real cluster provision succeeded unless Vagrant/Ansible output was actually observed.

## Change guidance

- Inspect the existing role, task, manifest, workflow, and README references before editing; preserve established names and capability boundaries.
- Keep default provisioning cluster-only. Add-ons must remain opt-in and must not change the default `VAGRANT_DEPLOY=cluster` path.
- Keep infrastructure changes idempotent and explicit. Avoid broad refactors or unrelated formatting.
- Keep Kubernetes access least-privilege and namespace-scoped. Review ServiceAccounts, Roles, RoleBindings, NetworkPolicies, and token mounting when changing platform components.
- Update `README.md` when a user-visible capability, command, dependency, or traffic path changes.
- Do not commit or push unless explicitly requested. Prepare changes on the current feature branch and report the exact validation results.

## Useful paths

- `Vagrantfile`: capability selection, VM definitions, SSH bootstrap, Ansible entrypoint
- `ansible/inventory.yml`: VM groups, addresses, CPU, and memory
- `ansible/playbook.yml`: role execution and Ansible tag boundaries
- `ansible/roles/common/`: shared host prerequisites
- `ansible/roles/rke2-server/`, `rke2-agent/`: RKE2 control plane and workers
- `ansible/roles/vip_lb/`: Keepalived/HAProxy VIP layer
- `ansible/roles/platform-bootstrap/`: platform namespaces, network policies, and bootstrap boundaries
- `ansible/roles/argocd/`: Argo CD installation/configuration
- `ansible/roles/github-rac/`: GitHub Actions Runner Controller resources
- `devops/cd/k8s/`: GitOps application base and staging overlay
- `.github/workflows/`: CI and reusable image/build workflows
- `scripts/validate.sh`: canonical local validation entrypoint
